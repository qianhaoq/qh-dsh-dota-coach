# A2UI replay review

The plugin implements an application-specific subset of [A2UI v0.9.1](https://github.com/a2ui-project/a2ui/blob/main/specification/v0_9_1/docs/a2ui_protocol.md), the current production version consulted on 2026-11-01. It does not claim full Basic Catalog conformance or a general-purpose renderer.

`a2ui.ts` defines the review catalog, strict component schemas, reference validation, ordered surface/data/component reduction, deletion and action resolution. The catalog ID is `github.com/qianhaoq/qh-dsh-dota-coach:review-v1`. Its components are Column, Row, DecisionCard, ReplayClip, ResourceSnapshot, EvidenceList and MatchOverview. Containers use a flat adjacency list rooted at `root`; this subset requires a bounded tree with distinct children. Leaf data bindings are catalog-defined decision/evidence IDs.

The model receives the catalog and record IDs. It chooses component types, grouping and order, returning a real `version: v0.9.1` / `updateComponents` envelope alongside its report or answer. The host validates the graph and records, then supplies `createSurface` and `updateDataModel` envelopes containing authoritative data. React consumes these framed message batches over the existing DSH remote/polling transport. This release does not stream partial model JSON or implement SSE.

Each local interaction creates an A2UI action envelope with surface ID, source component ID, timestamp, action name and context. The action is checked against the issuing component before opening the shared inspector. Reads use the existing host match/replay APIs, including their existing range and evidence checks. UI descriptions cannot introduce arbitrary HTML, URLs, code, tools or mutations.

New phase reports persist their UI descriptions in the same model call. An older cached report gets one separate presentation-only call, persisted on the session; its original analysis, evidence and generation timestamp are untouched. Failed presentation generation uses the same renderer with deterministic cards and does not automatically rerun the analysis. Interrupted presentation work settles to the fallback after restart. Follow-up surfaces persist with their answers; malformed optional UI cannot fail a valid answer or cause another model call.

The inspector joins a decision's replay window, pre-decision state, recorded actions, alternative, tradeoff, later observations and evidence. Timestamped records can seek the replay. Requested-time evidence remains separately labelled and can open its own window. `ResourceSnapshot` always refers to its labelled decision-time state, which can be earlier than an event or follow-up timestamp. OpenDota match details are read on demand. The player is a two-dimensional reconstruction from native demo records, not a recording of the Dota client's rendered video. Enemy visibility and unknown fields retain their original limits.
